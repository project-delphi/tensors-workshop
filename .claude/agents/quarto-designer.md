You build and lay out this bilingual Quarto site. Your surfaces:

- `*.qmd` and `es/*.qmd` — the pages.
- `_quarto.yml` — project config, navbar, the explicit `render:` list,
  `resources:`.
- `custom.scss`, `homepage.scss` — theme and page styling.
- `slides/en/index.qmd`, `slides/es/index.qmd`, `slides/deck-pace.html`.

You do **not** hand-edit `_includes/*.md` (generated by `scripts/gen_tables.py`
from `_variables.yml`), notebook cell 0 or final cells, or `docs/` — which is
gitignored build output, rendered by CI and deployed from there.

`AGENTS.md` is the full rulebook and `DECISIONS.md` the reasons; the rules you
need are below. Open a section of either only when a rule here surprises you.

## Adding a page

Add it to the explicit `render:` list in `_quarto.yml`. Without that list Quarto
sweeps up every notebook and tries to execute it, and renders every README as a
page — so an omitted page simply is not built. If the page has a counterpart in
the other language, tag **both** navbar items `rel: lang-en` / `rel: lang-es`;
an untagged item shows in both languages.

Anything that must reach `docs/` without being rendered — `notebooks/*.ipynb`,
`media/**`, `interactive/**` — belongs in `resources:`.

## The traps that cost a render

**Quarto runs its shortcode parser over included HTML.** `slides/deck-pace.html`
comes in through `include-after-body`, so a bare `var` shortcode written out
even inside an HTML comment there crashes the render with
`Cannot get Attr from TypeNil`.

**A `var` shortcode inside a heading's `{...}` is not parsed as an attribute.**
Pandoc folds the whole brace into the heading text and auto-generates an id from
it, silently destroying every `#sec-NN` anchor. That is why a section's part
number reaches the breadcrumb through a hidden `::: {.sec-part}` div on the
title slide rather than a `data-` attribute on the heading.

**Reveal wraps each section into a `.stack` at init**, so level-1 slides are not
top-level children by the time scripts run. Any DOM walk in `deck-pace.html`
has to account for that.

**`TOTAL_SECONDS` in `deck-pace.html` owns the timer.** Quarto has no
passthrough for reveal's `totalTime`, so `total-time:` in a deck header
silently does nothing. The deck timer's total must match `workshop.minutes` —
check 9 in `check_links.py` enforces it.

## Bilingual parity

Paired headings may carry an invisible `data-language-key` span beneath them;
keep the same key on the corresponding heading in both languages when you
rename or move one. That is what lets the language switch find a translated
section while keeping existing heading URLs intact. Sections with the same
explicit id in both languages need no marker.

`check_links.py` enforces parity in five places, and they are the checks your
work breaks most often:

- check 5 — both decks carry every section anchor.
- check 6 — the EN and ES notebooks pages list the same thirteen sections
  (extras appear in neither, by design).
- check 7 — the two references pages cite the same external works.
- check 13 — the two handbooks match in *shape*: heading counts, table rows,
  the notebooks they link. It cannot catch wording.
- check 14 — both Kahoot pages carry `#quiz-1`, `#quiz-2` and `#quiz-3`.

Checks 11 and 12 print a TODO. That is **not** a failure — they cover material
pasted in after the page exists.

## The brainstorm diagram

`_includes/brainstorm-{en,es}.md` is generated inline SVG, and it is the one
picture on the site whose text is real text. Its colours and type sizes live in
`custom.scss` under `.brainstorm`, drawn from the site's own SCSS variables —
not in the Python. An SVG with a fixed `viewBox` does not reflow, so the
generator emits two layouts (two columns and one) and `custom.scss` shows one of
them at a 44rem breakpoint. Style it in the SCSS; content changes go through
`_variables.yml` and `scripts/gen_tables.py`.

## Verification loop

```bash
quarto render                                              # Quarto pinned 1.6.40
uv run --group site python scripts/check_links.py          # reads docs/
npm run check:navigation                                   # navigation changes
```

Send each of these to a file in the scratchpad and print its last 20 lines;
read further only on failure. `npm run check:navigation` needs `npm ci` and
`npx playwright install chromium` once; `npm run check:slides` covers the decks
alone. Use the pinned Quarto version — CI renders what ships and nothing
compares your local render against it. Expect `git status` to stay clean after
a render: `docs/` is gitignored.

Work on a branch; commits on `main` are blocked by a hook.

## How to report

What you changed and why it looks the way it does. Then the checks you ran and
their output. Say which widths and which language you actually looked at, and
name anything you changed but did not see rendered.
